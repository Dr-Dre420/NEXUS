CORE ANALYTICAL PRINCIPLES
1. Separate OBSERVED, ESTIMATED, EXPOSED, SIMULATED, and FUTURE OBSERVED quantities.
2. Correlation is not propagation.
3. JLG/group liability is the primary propagation channel.
4. Default hierarchy: Branch -> Centre -> JLG -> Borrower.
5. Pairwise borrower relationships are secondary.
6. Healthy connected borrowers must not automatically become intervention-worthy.
7. Simulation is deterministic, assumption-driven, and not presented as a guaranteed forecast.
8. Model C is a hypothesis, not a guaranteed improvement over Model B.
UI wording must never imply that an exposure estimate is a realized event or that an association constitutes a causal finding; use the epistemic label and evidence type consistently in every view.

FINAL TEMPORAL CONTRACT - DO NOT CHANGE
Current Stress:
- Label is observed stress state at assessment time t.
- Prediction features must use information strictly before t.
- Same-time repayment/cash-flow evidence used to define the label cannot also be a feature.

Next-Period Stress:
- Borrower is currently non-stressed at t.
- Label is whether stress occurs at t+1 or configured future horizon.
- Features may use information available at or before t.

Propagation Vulnerability:
- Borrower is currently non-stressed at t.
- Borrower later becomes stressed.
- Hidden generator lineage indicates network contribution share >= 0.30.
- Prediction features may use only information available at or before t.
- Nothing observed in the interval after t and before the outcome horizon may enter prediction features.
- Future observed outcome and hidden lineage are evaluation-only.

Healthy-Borrower Protection:
- Measure unnecessary flags / interventions among borrowers healthy at prediction time and not stressed within the evaluation horizon.
- Break results down by exposure level.

STRESS DEFINITION
Implement a transparent operational stress definition in config/targets.yaml using observed repayment behavior and/or sustained cash-flow strain with persistence / repeated evidence.
- Stress labels never come from NEXUS predictions.
- Freeze target thresholds before held-out evaluation.

PROPAGATION ATTRIBUTION - FIXED PRIMARY THRESHOLD
Use:
propagation.meaningful_contribution_share = 0.30
Do not tune this target definition on validation.
Report sensitivity at 0.20, 0.30, and 0.50 as a robustness analysis only.
Scenario family labels never directly define the target. A seasonal event can produce real borrower stress; hidden lineage determines whether a specific borrower outcome is propagation-attributed.

COUNTERFACTUAL LINEAGE ATTRIBUTION
Because the synthetic world is nonlinear, estimate network contribution by deterministic same-seed/state counterfactual rerun:
- Full world: network-transfer mechanisms enabled.
- Counterfactual world: same seed/state with network-transfer mechanisms disabled.
- Compute the downstream shortfall difference between the two runs.
- Normalize that difference into a contribution share using the configured denominator.
- Use this lineage only for evaluation / target construction.
- NEXUS prediction code must never read hidden lineage.

GENERATOR / DETECTOR / SIMULATOR SEPARATION - CRITICAL
The financial world generator and the detector must not be self-fulfilling.
Shared forward financial mechanics belong in src/mechanics.py.

src/mechanics.py:
- forward cash-flow rules
- repayment / delinquency rules
- group-liability / coverage mechanics
- shared-income / affordability mechanics
- contains NO hidden lineage and NO detector scoring

src/data.py:
- generates the synthetic world
- creates scenario metadata
- creates hidden lineage
- may import mechanics.py
- must NOT import detector propagation or model-scoring code

src/simulator.py:
- may import mechanics.py
- applies shocks to cloned state
- advances the clone using the same forward financial mechanics
- must NOT import or read hidden lineage
- must NOT call evaluation-only attribution functions

Only evaluation / target modules may access lineage:
- src/targets.py
- src/evaluate.py
Tests may inspect lineage for validation but operational prediction code must not.

JLG / GROUP REALISM
- Default JLG size: around 5 borrowers.
- Centres contain multiple JLGs, roughly 15-30 borrowers as a configurable range.
- JLG/group liability is the primary network mechanism.
- Centre-level effects are weaker than direct JLG exposure.
- Do not model one group-liability mechanism as dozens of equivalent borrower-borrower liability edges.

MULTI-CYCLE LOANS / AFFORDABILITY
- Borrowers support multiple loan cycles with realistic origination gaps and changing principal / instalment profiles.
- Household affordability and multi-lender debt obligations are first-class risk context.
- Do not pretend synthetic external debt is actual bureau data.

SCENARIO FAMILIES
seasonal_downturn
- Regional/sector pressure affects several borrowers.
- Recovery is possible.
- Some group coverage may occur.
- Per-borrower propagation attribution depends on hidden lineage.
- Hard negative for correlation vs propagation.

isolated_shock
- One borrower receives a personal income/expense shock.
- Connected members may cover minor shortfalls.
- Destination borrowers should remain below the 0.30 contribution threshold.
- Tests graph overreaction.

individual_deterioration
- Borrower-specific gradual decline over about 6+ months.
- No meaningful network contribution.
- Tests independent deterioration.

propagating_stress
- Source borrower loses cash buffer.
- Shortfalls create group/connected financial burden through financial mechanics.
- Destination borrower later deteriorates with lag.
- Hidden lineage records the pathway and contribution share.

- Weekly or fortnightly repayment cadence; preserve exact due/payment timestamps.

GROUP-FIRST PROPAGATION EXPOSURE
Build the exposure computation BEFORE Model C.
1. Aggregate JLG/group liability into one group-level exposure signal, such as covered shortfall relative to group capacity.
2. Pass that group exposure once to each member.
3. Do not noisy-OR across every stressed member in a large JLG.
4. Aggregate only across distinct semantic channels, for example:
   - group liability
   - shared income
   - bilateral guarantee
   - centre context

Preferred bounded distinct-channel aggregation:
network_vulnerability(B,t) = 1 - Product_c (1 - clipped_channel_exposure(c,B,t))

Use explicit safety bounds only. Do not use hidden caps as calibration.

CALIBRATION / OPERATIONAL SCORE
- Calibrate model probabilities on validation only.
- If network exposure is shown as probability-like, calibrate it against Propagation Vulnerability rather than treating arbitrary [0,1] numbers as equivalent.
- Model C CALIBRATED OUTPUT is the single operational risk score.
- Model C drives risk badges, state transitions, and recommendations.
- The alpha decomposition is explanation-only and must not independently drive action:
  decomposition_risk = alpha * calibrated_individual_stress + (1-alpha) * calibrated_network_exposure
- Freeze calibration parameters, alpha, transmission factors, stress thresholds, and action thresholds before held-out testing.
